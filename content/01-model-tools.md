# 第 1 部分：模型的工具

> 状态：学习资料整理完成。下述执行链来自作者提供的 `stage1-agent-tools.zip`；尚无作者独立实现 Agent Tool 的运行记录。

## 起点：一次人工充当工具的经历

作者曾在 ChatGPT 中询问服务器静态 IP 的配置。模型提示命令，作者在服务器执行，再把结果复制回对话。作者注意到自己主要负责执行和搬运结果，因此提出问题：能否让模型自己调用能力、直接观察结果，并继续判断下一步？

这个问题延续第 0 部分的最小循环：LLM 需要外部动作时发起 Tool Call，工具输出以 Tool Result 进入上下文，再次调用模型。

## 本阶段的理解

> Tool 是 LLM 与外部世界之间的可执行接口。

作者的资料对 Anthropic、LangChain、OpenAI 与 Google ADK 的工具观做了概括。本页将其作为学习输入，不把这些中文概括当作官方逐字引文。实际可用的工具不仅需要执行能力，还应考虑输入约束、权限、文件状态、运行边界、输出大小与错误反馈。

| 层次 | 主要责任 |
| --- | --- |
| Tool 自身 | 输入 Schema、工具专属校验、执行、结果整理 |
| Agent 运行框架 | 执行前 Hook、权限、调度、执行后 Hook、错误回灌、再次调用模型 |

学习包梳理的典型链路：Tool Call → Schema → 工具校验 → PreToolUse → Permission → Execute → Result / Error → PostToolUse / PostToolUseFailure → LLM。不同实现可能调整具体步骤与顺序，这里是资料中的研究模型，并非已运行的本站程序。

## 为什么从 Read、Edit、Bash 开始

| 工具 | 代表的能力 | 核心问题 | 学到的机制 |
| --- | --- | --- | --- |
| Read | 获取外部状态 | 大文件、二进制、Token 限额与重复读取如何处理？ | 范围读取、输出预算、文件 mtime、同范围去重、错误回灌 |
| Edit | 修改外部状态 | 如何确保修改基于模型已读的文件版本？ | Read-before-Edit、旧文本唯一匹配、mtime、写前二次校验、patch |
| Bash | 执行通用系统操作 | 复合命令如何判定、授权和隔离？ | 命令解析、只读分类、权限、沙箱、超时、后台任务、输出上限 |

### Read

资料中的 Read 链包含路径及范围参数、输入校验、读取权限、按范围读取、大小与 Token 预算、结果整理及失败回灌。重点是控制模型能看到哪些外部信息、以什么形式看到，以及上下文成本。学习包的细节来自 Claude Code 相关的学习摘录，不代表本站复现了其实现。

### Edit

资料中的 Edit 链强调读后写：先记录模型读取的内容和修改时间，检查 `old_string` 的匹配与歧义，在执行前再次核对文件状态，然后生成 patch 并写盘。这是在避免文件被别人修改后仍按照旧视图覆盖内容。学习包讨论的 `readFileState` 和 stale write 是研究对象，本站尚未实现。

### Bash

Bash 处理的是高自由度命令，包含管道、重定向、变量、复合命令等。资料把 **Permission**（是否允许动作）与 **Sandbox**（允许后可触碰哪些资源）明确分开；还包括超时、前后台执行、输出限额与错误处理。不能仅凭命令字符串的前几个字符做安全判断。

## 架构变化：REV 00 → REV 01

第 0 部分用一个抽象 Tool 表示外部能力。本阶段把它细化为 Tool Call、检查与权限边界、Read／Edit／Bash，以及回到 LLM 的 Tool Result。第 0 部分“不需要工具时直接返回”的分支仍成立。新增的是**对工具内部机制的理解**，并非已经写出可运行的工具系统。

其他工具，如 FileWrite、Glob、Grep、WebFetch、WebSearch、MCP、AgentTool 和 Task 系列，仅作为后续地图。**工具实现存在、暴露给模型、允许执行**是三个不同条件，不能混为一谈。
